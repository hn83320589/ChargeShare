# 第 4 章　技術選型：在限制下做取捨

## 學習目標

- 區分「被規定的」與「可以選的」技術
- 用**決策框架**比較選項，而不是憑喜好
- 理解每個選擇的**代價**，以及刻意**不選**什麼

---

## 4.1 先分清楚哪些不能選

題目已規定：Python 3.12+、FastAPI（含 WebSocket）、SQLite + SQLAlchemy 2.x + Alembic、pytest、不用 Docker。
這些是**限制**，不需要討論優劣，要討論的是「在這些限制下怎麼用好」。

真正可選的有：前端技術、套件管理、程式碼品質工具、非同步模型、時間與數值的表示方式。

---

## 4.2 決策框架

遇到多個可行方案時，本專案依序考慮：

1. **可測試性**——容易寫測試嗎？
2. **可讀性**——六個月後還看得懂嗎？
3. **一致性**——符合專案既有模式嗎？
4. **簡單性**——是最簡單的可行方案嗎？
5. **可逆性**——之後要改有多難？

排序本身就是一種價值觀：在這個專案裡，「好測試」比「效能好一點」重要，因為計費錯誤的代價遠高於多花 10 ms。

---

## 4.3 各項選擇

### 前端：Jinja2 + HTMX + Chart.js（不用 React）

| 選項 | 優點 | 缺點 |
|---|---|---|
| React / Vue SPA | 互動能力強 | 第二個專案、建置流程、API 設計，對 3 個頁面太重 |
| **Jinja2 + HTMX** | 伺服器端渲染、幾乎不用寫 JS、和 FastAPI 天然整合 | 複雜互動較難 |
| 純 JavaScript | 無相依 | 要自己處理局部更新 |

需求只有：狀態卡片每 5 秒更新、帳單「標記已繳」、一張曲線圖。HTMX 用 HTML 屬性就能完成局部更新：

```html
<div id="chargers" hx-get="/admin/chargers" hx-trigger="every 5s" hx-swap="innerHTML">
```

圖表交給 Chart.js（約 30 行 JS）。兩個函式庫都**放進專案**（`static/vendor/`），不依賴 CDN，離線也能展示。

### 即時更新：輪詢（不用 SSE / WebSocket）

儀表板每 5 秒輪詢一次。SSE 更「即時」，但要處理重連、連線數、代理伺服器緩衝。
5 秒的延遲對管委會看儀表板完全足夠。**選擇滿足需求的最簡單方案。**

### 套件管理：uv + uv.lock

題目要求「鎖定的相依版本」。uv 原生產生 lock 檔、速度快，CI 用 `uv sync --locked` 保證和本機一致。
同時保留 `pip install -e .` 的路徑（審查回饋），降低使用門檻。

### 資料庫存取：同步的 SQLAlchemy

FastAPI 是非同步的，直覺上會想用 async 的資料庫驅動。但本案例：

- SQLite 是本機檔案，單筆查詢在微秒到毫秒等級
- 只有 8 支樁、每分鐘一筆讀數，負載極低
- 同步程式碼較好寫、好讀、好除錯

所以選擇在 event loop 中直接執行同步的資料庫操作。這是**有意識的取捨**：
如果樁的數量增加到上千支，就該改用 async driver 或執行緒池。這個前提寫在 README 的已知限制。

### 數值表示：整數與 Decimal，不用 float

| 量 | 型別 | 理由 |
|---|---|---|
| 功率 | `int`（W） | 3.75 kW = 3750 W，整數運算沒有誤差 |
| 電量 | `int`（Wh） | 題目要求 0.001 度 = 1 Wh，剛好是整數 |
| 分攤中間值 | `Fraction` | 線性分攤會產生 1/3 這種數，用分數保持精確 |
| 金額 | `Decimal` | 0.1 + 0.2 ≠ 0.3 的問題在錢上不能接受 |

```python
>>> 0.1 + 0.2
0.30000000000000004
>>> Decimal("0.1") + Decimal("0.2")
Decimal('0.3')
```

### 品質工具：ruff + pytest + GitHub Actions

ruff 同時負責 lint 與 format；CI 在 Python 3.12 與 3.13 兩個版本上跑 lint 與全部測試。

## 4.4 刻意不引入的東西

不引入新套件也是一種選擇。本專案在幾個地方**刻意用標準函式庫**：

| 需求 | 常見做法 | 本專案 | 理由 |
|---|---|---|---|
| 密碼雜湊 | bcrypt / passlib | `hashlib.scrypt` | 標準函式庫已足夠安全 |
| 日期加月份 | python-dateutil | 自己寫 10 行的 `add_months()` | 只需要這一個功能 |
| 設定檔 | PyYAML | `tomllib` | Python 3.11+ 內建 |
| 對照圖 | matplotlib | 直接產生 SVG 字串 | 只需要一張圖 |

每多一個相依，就多一份升級、漏洞、授權的負擔。只用到一小部分功能時，自己寫往往更划算。

> 💡 **教學重點**：「不要重新發明輪子」是好原則，但「不要為了一個螺絲買整台車」也是。
> 判斷標準是：自己寫的版本能不能在 20 行內寫完、而且有測試。

---

## 4.5 選型清單與版本

```toml
# pyproject.toml（節錄）
requires-python = ">=3.12"
dependencies = [
    "alembic", "fastapi", "itsdangerous", "jinja2",
    "python-multipart", "sqlalchemy>=2", "uvicorn[standard]", "websockets",
]
[dependency-groups]
dev = ["httpx", "pytest", "pytest-asyncio", "ruff"]
```

確切版本鎖在 `uv.lock`。前端函式庫的版本（htmx 2.0.4、Chart.js 4.4.7）寫在提交訊息與 README 中。

---

## 小結

1. 先分清楚「限制」與「選擇」。
2. 用固定的決策框架比較選項。
3. 選滿足需求的最簡單方案，並記下前提（負載低、單一行程）。
4. 錢與電量不用浮點數。
5. 不引入相依也是一種設計決策。

## 思考題

1. 如果管委會要求「斷線時手機立即收到推播」，輪詢還夠嗎？你會改用什麼？
2. 本專案用同步資料庫存取。請估算：在什麼樣的樁數量與讀數頻率下，這個選擇會開始影響 WebSocket 的回應時間？
3. 找出專案中另一個「可以用套件、但選擇自己寫」的地方，評估這個選擇。
