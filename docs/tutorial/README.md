# ChargeShare 教學：從需求到程式的系統設計實戰

這份教學以 ChargeShare（社區充電樁共享管理平台）為完整案例，示範一個中型系統如何從一份題目需求，
一路走到可以上線、有測試、有文件的程式。重點不是「這個系統怎麼用」，而是**每一步為什麼這樣做**。

> 系統本身的使用說明見 [README](../../README.md)，設計決策紀錄見 [DESIGN.md](../DESIGN.md)，
> 驗收結果見 [TEST_REPORT.md](../TEST_REPORT.md)。

## 適合誰

- 會寫 Python，想學「怎麼把一個需求變成一個系統」的工程師或學生
- 寫過 CRUD 網站，想接觸**即時控制、硬體通訊、計費正確性**這類比較硬的問題
- 想看一個有完整測試與決策紀錄的範例專案

## 建議閱讀方式

1. 先讀第 1–3 章，建立全貌。
2. 第 7 章是技術核心，建議搭配原始碼與測試一起看：每個演算法都有對應的純函數與單元測試。
3. 第 10 章的除錯案例很適合單獨閱讀：每個案例都是「看起來對、其實錯」的經典情境。
4. 動手做：clone 專案、跑測試、改參數，再挑第 11 章的題目練習。

```bash
git clone https://github.com/hn83320589/ChargeShare && cd ChargeShare
uv sync
uv run pytest                                   # 149 個測試
uv run chargeshare simulate --dev --minutes 30 --speed 60   # 看 8 支樁跑 30 分鐘
```

## 案例一句話總結

> 一棟 120 戶大樓、8 支 7 kW 充電樁，只能用 30 kW。系統要即時控制每支樁的功率上限，
> 讓總和**任何時刻**都不超過 30 kW，並依時間電價正確收費——而充電樁韌體不穩定，會斷線、重開機、甚至電表歸零。

這個案例的價值在於它同時有三種困難：

- **控制**：多支樁共享有限資源，要公平、要穩定、不能超標。
- **正確性**：錢的計算不能差一毛，資料重送不能重複算。
- **不可靠的外部世界**：硬體會出錯，網路會斷，系統要在這種環境下仍然正確。

這三種困難幾乎出現在所有「軟體控制實體世界」的系統裡：IoT、能源管理、物流、支付。
